## STAB-5 open questions (phase 3 + 6 build, 2026-11-22)

Recorded while building; each is built the way described, so nothing waits on the answer.

1. **Receipt with `show_part_times_to_customers` off.** The brief says "only the order's promise, as today", but today's receipt prints no ready time at all. Built: off → the receipt is exactly as before (no time block). Should off print one line "Ready ~<promise>" instead?
2. **An as-ready line whose parts all land in the same minute** (or an unsplit as-ready line) prints "Karahi: ready ~2:20 PM". The brief names only the different-times and together cases. OK?
3. **Which time the customer sees.** Built as each part's land time plus the order's padding (`promise_ms − target_land_ms`), so "together" equals the order's promise and the parts use the same padding. The staff cart shows land times without padding. OK, or show the customer land times too?
4. **Parking orders** do not get the ready-time block (the brief says the takeaway token / receipt). Should parking too?
5. **Pass Done on a grouped row.** 03b §3.3 says Done sends the part that started last first. The Pass card has no start times (`PointLine` carries none), so the Pass sends from the last part back, and the KDS uses real `started_at`. Add `started_at` to `PointLine` (an additive 03b field) to match exactly?
6. **Fiscal submission.** The authority now gets one line per split line ("Karahi, 5 units") with summed amounts and taxes, the same shape an unsplit line had before STAB-5. Please confirm with the PRA sandbox run (manual owner step) that nothing else is expected.
7. **Credit notes** still print one row per part (05 v1.0.33 keeps them per line; voids and returns by count are phase 4).
8. **Earlier test drift fixed.** The exact-type tests for `LineDetail`, `LineView` and `SubmitInput` (from phases 1–3) had not been updated, so the tests typecheck was red at `730f8870`; fixed in `9b8557a` with ⚠️ markers.
