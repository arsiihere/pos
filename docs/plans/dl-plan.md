# DL Notification deep links — Implementation Plan (01d v1.3 §3.13)

> **For agentic workers:** every task is TDD (failing test first, record the failure, then implement). One task = one branch = one PR into `module-deeplinks` = one commit after review. Lanes run in **claude.ai/code cloud sessions**; the gate runs in **GitHub Actions** (`.github/workflows/gate.yml`). Board: `docs/plans/dl-status.md`. Same working model as `docs/plans/04-plan.md`.

**Goal:** a tap on a notification opens its place in the staff app (tablet, phone, Windows cashier kiosk), scrolls to it and gives it a 2 s brand glow; or shows "This item is no longer open." and stays. Requests open `AnswerSheet` on top (DL Q-1 (a)), notices open `NoticeSheet` on top (DL Q-3 (a)). Kinds with no staff-app place keep today's tap (DL Q-0a (a)). The KDS never reads `target`.

**Spec:** `docs/specs/01d_Notifications_Requests_Spec_v1.3.md` §3.5 note, §3.10 note, **§3.13**, §4.6, §5.4, §8.1, §8.2, **§10.9d tests 69–97**, §12.8 (APPROVED, owner 2026-11-18 10:05 PKT). Pointer bumps: 02a v1.1.7 (§6.14, §6.15, §8), **02b v1.0.15** (§6.12, §6.13, **§6.18a `order-view` gains `order_type` and the current `seating_id`, test 52**, §8), 03a v1.2.5 (§4.2), 03b v1.0.9 (§6.21), 04 v1.0.6 (§3.5). 03c is unchanged. Review: `docs/reviews/dl-deeplinks-hostile-review.md` (B1–B3, M1–M6 fixed in v1.3). Story: `docs/stories/deeplinks-refined.md`.

**Starting point:** `module-deeplinks` @ `af8fddd5` (= `main` `049f6ce` + the approved spec set). Every path below was checked with `git grep` on `origin/module-deeplinks`.

**What is different from 04's plan (and why):**

| 04 did | DL does | Why |

## Global rules (every task)

- **Branches:** integration branch `module-deeplinks`. Task branch `lane-<L>/dl-<task>` (e.g. `lane-H/dl-h1`, `lane-Cs/dl-cs6`). Base = `origin/module-deeplinks`, or the track's previous **unmerged** task branch (stacked; PR body says `Stacked on #<n>`). After a lower PR merges: `git rebase --onto origin/module-deeplinks <old-base> <branch>` and `git push --force-with-lease`, **only on your own task branches**.
- **PR:** REST only: `gh api -X POST repos/arsiihere/pos/pulls -f title='<task>: <title> [01d v1.3 §x]' -f head=… -f base=module-deeplinks -f body=…`. Body: spec sections; tests added, each with its failing-first output line; statement counts / reads per tap asserted; Readings; `Needs: #…`; ends with the 🤖 Claude Code line and the session URL. Label `lane:<L>` (`lane:H`, `lane:Cs`, `lane:Cp`, `lane:T`). Rebase-merge only.
- **Commit:** one per task after review, author `Arslan Ahmed Arif <arsiiahmi@gmail.com>` (`git -c user.name=… -c user.email=… commit`), trailers `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` and `Claude-Session: …`. Message cites the spec: `feat(alerts): <title> [01d v1.3 §3.13.x; tests N]`; Cross rows `feat(<module>): <title> [<module> vX §y; 01d v1.3 §4.6 L-4x]`. Review fixes squashed in before the PR is ready.
- **Review:** after the implementation, a **fresh reviewer subagent** (opus) reads the cited spec sections, the diff and these rules. **HIGH** tasks get a second fresh reviewer focused on lock safety (no amount, item or reason on a lock view, AD-81), command flow (an answer or a `closeMany` never aborted by a `link`, M4; `MarkAlertsSeen` once per alert), permissions (B2: an approver never loses `AnswerSheet`), table locks and drafts (M5), statement counts. Fix rounds > 2 → STOP.
- **TDD:** test names cite the spec: `it('[01d #74] …')`, `it('[02b #52] …')`; un-numbered support tests cite the section, `it('[01d §3.13.6] …')`. Real tables and real events on the hub; on the client, the existing fakes (`apps/client/src/features/alerts/test-fakes.ts`, the staff api fakes) — never a mock of another lane's unmerged code. Fake timers for the glow length; **no timing asserts in the gate** (03a AD-32: the 2 s length is read from `--motion-glow`, never measured).
- **Statement counts:** v1.3 adds **no** hub statement (§3.13.1 "Statement counts"). Every count the spec names is pinned with `statementCounter(db)` (`apps/hub/test/helpers/statement-counter.ts`). A count that moves is a **STOP**, never a Reading. **AD-12 style:** a count test that boots `createTestHub()` and is not about a guard calls `resetLineGuard()` / `resetDayCloseGuard()` / `resetMergeGuard()` right after it, so 04's boot registrations do not shift the count; a fake kind registered by a test (a throwing `link`, a `{ type: 'nope' }` link) is removed with `unregisterAlertKind` in `afterEach`.
- **Tests you run:** your own files (`TMPDIR=/dev/shm pnpm vitest run <files>`) plus the existing tests of every file you changed, and `pnpm --filter <pkg> typecheck`. **The full gate runs in CI** (`TMPDIR=/dev/shm flock /tmp/pos-gate.lock -c "pnpm -w typecheck && pnpm -w lint && pnpm -w test"` if you run it locally). **Never** `pnpm test:perf`, printer, hardware or power-loss checks; never stop or restart Postgres (cloud 5433).
- **Files:** only the files of your task row. **Lane file ownership:** H owns `apps/hub/**` and `packages/events/src/alerts.ts` after cs1; Cs owns `apps/client/src/features/alerts/**`, `StaffApp.tsx`, `shell/**`, `tables/TopBar.tsx`, `orders/contracts.ts`, `i18n/{en,ur}.ts`; Cp owns `packages/ui-kit/**`, `orders/table-view/**`, `orders/view/OrderView.tsx`, `orders/zones/ZoneStock.tsx`, `tables/map/**`, `tables/sheet/TableSheet.tsx`, `orders/late/LateCard.tsx`, `features/pass/**`. A row that names a file of another track says so (Cross). A test that only pins a value an approved row changes may be edited by that row: list it under **Readings**. Anything else (a contract change, a spec–code mismatch, two specs disagreeing) → **STOP**: STOP block in the PR body, label `needs-ruling`, owner answers from the GitHub app; other tasks go on.
- **No merged-file edits:** never edit a merged migration, an approved spec file (`docs/specs/*`), another module's test except as a listed Reading, or this plan / the board (the integrator edits `dl-status.md`).
- **Do not build:** "food ready" to waiters (DL Q-0b (a), DL-F1, §12.4); a `link` for `station_overload`, `kds_offline`, `printer_problem`, `no_approver`, `test_alert` (DL Q-0a (a)); any KDS change; a leave-confirm guard (M5: drafts are kept instead); the Android notification intent (gap G-2).
- **Wire:** the hub emits only the strict `AlertLinkTargetSchema`; the client reads `target` through `.nullable().optional().catch(null)` (M2). `my-requests` rows keep `lock` only. **Logs:** a `link` throw is silent (no log line, as AD-82). Ids and counts only, never names, PINs or phones.
