### `selectSnapshotPrices` time-free, and the same answer as 08a I7?

Time-free: ✓. Same answer: the dominance rule keeps every row I7 could pick at any hub time (run 2 table, still valid). On the hub, though, `effectiveMenuPrice` breaks ties with `later()` = (`created_at`, then `price_id`) (`prices.ts:25`). With every `created_at` set to 0, only `price_id` decides. In production `price_id` is a ULID from the same clock (`ids.ts:12`). Two price POSTs can still interleave: A reads `now` = 100 and mints its id at 102, while B reads `now` = 101 and mints at 101. Then the hub picks A where the cloud picks B. The test clocks (`clock.ts:12`) and id generators (`ids.ts:18`) are separate, so a test that sets `created_at` explicitly can also disagree. **Same answer only after t-1.**
