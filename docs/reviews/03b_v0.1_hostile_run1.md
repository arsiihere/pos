## Races and transactions — summary of what holds

| Race | Holds? |
|---|---|
| Two screens Done the same line | Yes — single writer + stage guard (test 10). Client should treat the loser's `ITEM_WRONG_STAGE { stage: 'done' }` as success, not an error toast (n). |
| Done vs UndoDone vs Handover vs Ready | Yes in the writer; but Ready lifecycle leaks (M-9) and re-target loses the alert (M-7). |
| Forward-only projection writing `print_jobs` in the event tx | Holds live; **fails on catch-up / first deploy (M-2)** and **can block fires (M-3)**. |
| Worker plain statements outside `writer.run` | Safe: better-sqlite3 is synchronous and `writer.run` has no `await` (`writer.ts:50-90`). The real race is render vs `sent_at` across the worker's own `await` (M-5). |
| Crash between `sent_at` and ack | Holds (REPRINT resend, D24) — but then double with fallback (M-4). |
| Boot step 5 vs fallback grace | Holds, minus n-5. |
| Head-of-line per printer | Inherent for a dead printer; **self-inflicted** for no-status / post-write status errors (M-6) and stale slips (m-14). |

## D24 / R8 — can a fired ticket go missing? can a printer block a command?

- **Missing:** yes — `screen` station without printer and dead KDS (M-13). Otherwise no, once M-4 / M-5 are fixed.
- **Blocking:** yes — a throw in the `kitchen_tickets` fold rolls back the fire / command (M-3). Network never blocks (worker outside tx) ✓.
