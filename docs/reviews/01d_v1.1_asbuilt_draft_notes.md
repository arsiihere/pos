## Unresolved (v1.0 text the code does not meet, and no AD covers it)

No rule was invented for these; each needs the developer.

1. **§7 "never `card` text or `details`" in logs vs. the whole-tick catch** (final review m-1). `tick.ts` logs the raw `err` of a failed tick; a `JSON.parse` error on `details_json` (reached through `close` / `listOpen` in a tick) can echo its input. Every other 01d log site logs name and code. AD-109 covers only the key name. Options: log `{ tick, err: { name, code } }`, or accept.
2. **§3.3 rule 4 (d) "No path skips the count" vs. a throw in `pinFailed` / the hook-draft `tx.append`** (final review m-3). The counting transaction rolls back for both PINs (symmetric, no oracle) on a bug path. AD-99 guards only the raise. The draft states it as a residual; a ruling is still needed.
3. **§5.1 "retention continues next hour" vs. the 00 sweeper** (final review m-5). A throw in `purge` leaves `retentionDays` unset, so 00's and 01d's purge re-run every 15 s for the rest of the maintenance hour. A 00 deferred minor, now reachable from 01d.
4. **§3.5 read-only contract "enforced, not trusted" vs. `Statement.database`** (final review deferred #1). A prepared statement from the read-only view still exposes the raw connection; only a deliberate bypass reaches it. Stated as a residual in §3.5.
Not counted as unresolved (an AD covers it): whether `stuck_alerts` stays a required field of 01a's `ConfigStatusResponse` or becomes `.default(0)` (final review m-2) is part of the AD-123 approval in "Contract changes".
