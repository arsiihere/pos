## 3. New findings (in the v0.5 lines only)

### R-1 The "live `recovery` token" read has no column to read — MINOR, TXT

**Where:** §6.11 Processing ("a live `recovery` bootstrap token exists …", "Statements: 1 read of live `recovery` tokens").

**Problem:** `admin_bootstrap_tokens` (`db/migrations/0002_devices_sessions.sql:50-58`) has no `issued_by` column. `issued_by` exists only in the `AdminBootstrapTokenIssued` payload (`auth/bootstrap-tokens.ts:37`), and migration `0027` (§5.1) does not add it. So a builder cannot tell a `recovery` token from a `setup`, `cli` or `restore` one with one read.

**Fix (simplest, no migration):** check for **any** live bootstrap token, `consumed_at IS NULL AND expires_at > now`, the same test the expiry `UPDATE` uses (`bootstrap-tokens.ts:15-20`). Every bootstrap link signs in the same way (M42), so any live one is a working admin path. Issuing a new one would also expire it. Change the page text to "An admin link was already made — it works until <time>". Test 16a stays as it is.

### R-2 `issueAdminBootstrap` cannot take the caller's device — NIT, TXT

**Where:** §6.11 (`device_id` = the caller's device), H-7.

**Problem:** the function writes `device_id: 'hub'` itself (`auth/bootstrap-tokens.ts:40`) and has no device parameter. The spec's call, `issueAdminBootstrap(tx, 'recovery')`, cannot carry the caller's device.

**Fix:** H-7 names the new parameter, for example `deviceId` (default `'hub'` for setup, CLI and restore).

### R-3 The 05 version cited is not on this branch — NIT, TXT

**Where:** §3.3, N-8 line ("05 v1.0.34 §3 request kinds").

**Problem:** this branch and the README carry 05 **v1.0.32**. v1.0.34 exists only on `fix/stab-tablet-pairing` (`120811dc`). The rows it cites are the same in v1.0.32 (`05_Billing_Spec_v1.0.32.md:653-657`).

**Fix:** cite "05 §3 request kinds (`shift_variance`, `petty_cash`)" without a patch version, or cite v1.0.32.

### R-4 Two v0.5 edits have no ⚠️ marker — NIT, TXT
