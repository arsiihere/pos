## 2. Attack results by area

1. **Races and ordering.** The serial writer (`engine-host/writer.ts:51-79`: the reducer folds inside the transaction, and the swap happens after COMMIT) and `tickPass` (`alerts/tick.ts:378-388`: one `now` per pass, ticks in order) make submit vs `fires` vs `fires_alerts` vs taps vs config apply safe as transactions. The bugs are in what a transaction computes: findings 2, 3 (submit), 4 (boost during a freeze or cascade), 5 (lane Off), 6 (day close), 17 (an Undo tap racing the close pass), 19 (two returns). Two submits on the last unit are serial (test 74). The `configStale` vs hook race is closed (S:399, "every hook run also re-evaluates it"). A return while the tick fires "the old line" cannot happen: a return needs a `served` line.
2. **Replay.** I tried a 20-event log for each listed source. `overload_open`, `red_since` and `skipped` are host memory and affect only `fires_alerts.due`, never `EngineState` (P-7). The exit window is replay-safe as fixed (removal only in listed folds). The checkpoint `last_seq` and `business_day` are correct (G2 #5). `ENGINE_REPLAY_EVENTS` = the handled types (test 94). The upcasting of `StockAdded` `reason` is additive. **One break:** `draws` read through `dayDraws` (finding 9). Folds of absent ids are unspecified (finding 6b).
3. **Promise correctness.** It breaks without a boost through: a fired line not yet started (2), immediate lines placed before pass 1 (3), a capacity drop inside the freeze (5), and day close (6). Padding is never consumed (slack from `T`, S:238). The keep is held by the pass order. Routing to an alternate uses only the alternate's free capacity, so it is consistent. `ItemsReleased` and the `max_late_ms` cap are as specified. The `StockAdded` re-plan (M7) is correct for slot stations and wrong for batch stations (10) and frozen lines (14).
4. **Capacity math.** Profile add and remove with units > 1 are correct. The freeze boundary at exactly `fire = t + freeze` is consistent: frozen means `≤` (S:222), the re-plan's fixed set uses `≤` (S:249), and `crossed` uses `(last, now]` on `fire − freeze` (S:307). COOKING `live_endsAt` is missing in `planOrder` (2b). Auto-fill is slot-only (S:291). Batch freshness is capped per line by `max_early_ms`. The lanes edge case is finding 20c.
5. **Money and audit.** `EngineState` and every 03a event carry no `_minor` field (S:150-201, §4.2). Confirmed: 03a moves no money itself. The D28 `remake` bill effect is handed to 04 (S:500). The `fix` effect is **not** handed to anyone, and it double-charges (finding 11).
6. **Bounds.** Sync `200` ≤ 32: 01b v1.4.1:169 (≤ 27) + 5 builder statements = 32. Correct (B-8). `fires` is 0 reads, and idle opens no transaction. `fires_alerts` is 2 + ≤ 1 + 01d, using `alerts_open_kind` (`0006_alerts.sql:33`). Boot: step 2 = 2, step 3 = 4 + 2, step 6 = 0. All consistent. **"≤ 250 re-placed" vs the drill's 702 does not hold** (finding 1). The `next_alert_due_at` bound contradicts the replay budget (15). The re-plan count per `StockAdded` is unbounded (12).

Every §4.2 event has a writer.
