## Checked and OK

- **H1-1 safety, every path:** another void (rule 6 (b) on both paths, same transaction); comp raise, direct comp and `applyComp` (line guard on planned ids; `deal_part` is never comped, `comp-line.ts` `check`); RemoveItems of a locked deal's stage-1 part or of a parent whose child is locked (planned ids); weight (line guard; voided line refused, Q-3); merge / split (`checkMergeGuard`); served / done / returns only advance stage and touch no ledger counter. So `apply`'s own lock really is the only void / comp lock on those lines. (The foreign-close hole is H2-1, a different mechanism.)
- **One stock pass:** `stockEffects` array form books every earlier draft and effect before the next (`stock.ts:549–553`); move-before-void per line is right because `moveDrafts` reads the unshrunk line and a cooking / done line holds `reserved = 0`; overlapping direct entries on one line give the same proportional shares.
- **One line-change pass:** `linesAfter` sums units per line, so one call over all entries gives exactly one `OrderCancelled` or `OrderFoodCleared`.
- **Per-line dispositions (OQ-C / OQ-D):** "at least one moved", served / no-draw → wastage, stored `moved` re-checked on approve with `hint` — consistent with V3, §3.4, §8, §9, apart from H2-2 / H2-5.
- **Money:** `voidUnits` moves a comped share to `comp_voided_minor` with billed unchanged; `pendingVoids` / To 05 subtract `refund_minor` only; pending-weight void refunds 0 (`refundable_minor` 0); approve amount = raise amount holds under V8.
