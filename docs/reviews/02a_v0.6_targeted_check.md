## 4. Observations (no severity, no action needed for approval)

- **O-1 (#10):** "count of step-0 recipients in the `AttemptSent` draft" (S:203). The rows are `RecipientRow { staff_id, device_id, for_staff_id, set }` (`alerts/targets.ts:49-54`), and some can be device rows or absent-owner marker rows. Say "distinct non-null `staff_id`s of step 0" so the count is the number of people and test 50b's 0 is well defined.
- **O-2 (#9):** after #9, `TABLE_NOT_OPEN` (§9, S:537) is thrown only by the common rule "no seating and no `seating_id` given" (S:354). Every seating command requires `seating_id` in its payload, so the code may now be unreachable. Worth a check when §9 is built; no behaviour depends on it.
- **O-3 (#2):** a non-holder with `take-order-anywhere` can still take the lock deliberately with Open (§3.2 S:114, "Lock; holder unchanged"). That is an explicit user action, not the stale-draft path #2 was about, so it is not a finding.
