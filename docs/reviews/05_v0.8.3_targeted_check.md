## Targeted checks (what holds)

- **H17-1 gate, all paths.** The gate never strands a split (proof in the status row; 0 stuck / 0 cash-only stuck in every setup, both seeds). It is consistent with §3.3 rule 8 (close needs `B = 0`), §6.12's zero-total close (a split at `T = 0` has `B = 0`, so no `in` and the close takes it), the check bill (B17 prints `cash_due` of an unpaid split, `B > 0`), `RemovePayment` (a removed cash leg can leave `B < 0` on a sale; only the refund due shows, RP case) and refunds (an `in` keyed while owed a refund is refused in every reopen, column I).
- **Tax never includes rounding** in either price mode, with compound pairs, inclusive back-calculation and the service charge (column J, 0 everywhere).
- **Money in = money out.** Per bill Σ tendered − Σ change − Σ refunds = Σ sale − Σ credit; per shift expected cash = the replayed drawer; per day takings = Z net + carried forward − brought forward (columns G, K, L).
- **Frozen rounding rule and rate changes.** Mid-bill and pre-reopen step changes change nothing (frozen, H16-2); reopens after a rate or `PK-PB` switch close at today's rates with the credit at the original's (Q-1 §27), every line-change kind, 0 failures.
- **Text fixes:** §3.6 / §12.7 / #21 (H17-3), §6.30 (H17-4), §8 bill screen, #15 / #20b / #20c all match the model.
- **Blind count:** unchanged since run 17; no frame carries `expected_minor` / `variance_minor` before the count (§6.30 :1269, §3.11 :576).
