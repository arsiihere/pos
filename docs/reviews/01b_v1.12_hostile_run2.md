## MAJOR

### R2-M-1 — §5.1c contradicts itself on the `directory_version` bump
**Where:** §5.1c, the sentence before the B-5 block: "in one statement so a tenant's `directory_version` rises once for the file". The closing parenthesis says: "Several statements … bumps `directory_version` by 2".
**Problem:** the file has two `UPDATE tenants` statements: one after the Pass CTE and one after the B-5 CTE. On every pre-v1.12 tenant both statements change rows, so the bump is +2. The text claims both "once" and "by 2". A builder cannot tell which one the tests should pin.
**Fix (recommended):** after the two `ALTER`s, write one data statement. It chains the data-modifying CTEs `new_roles` → `pass_grants` → `hou_grants` (`hand-over-unpaid` for active `owner` / `manager`, `ON CONFLICT DO NOTHING`). It ends with one `UPDATE tenants … WHERE tenant_id IN (SELECT tenant_id FROM pass_grants UNION SELECT tenant_id FROM hou_grants)`, which gives +1 per changed tenant. Postgres allows several data-modifying CTEs in one statement, as `0015` does. Then delete the parenthesis. If two statements stay, delete "in one statement … rises once".
