### R2-m-2 — Composer text, read literally, emits a `0` clip
**Where:** §8 Voice clips, `tokenClips(n)`: "thousands `t` → `<t>`, `thousand`; hundreds `h` → `<h>`, `hundred`; rest `r`: `r` in 1–19 → `<r>`; else `<tens>` then `<units>` if units > 0".
**Problem:** no "when `t > 0`" / "when `h > 0`" and no "`r = 0` → nothing"; literally 1015 → `1 thousand 0 hundred 15`, and 300 → `3 hundred 0`. There is no `0.mp3`, so the "missing clip → chime only" rule silences those tokens. Test 49's examples are right; the rule text is not.
**Fix:** "`t > 0` → `<t>`, `thousand`; `h > 0` → `<h>`, `hundred`; `r = 0` → nothing; `r` 1–19 → `<r>`; else `<tens·10>` then `<units>` when units > 0". Test 49 adds 300 → `[3, hundred]`, 1100 → `[1, thousand, 1, hundred]`, 2010 → `[2, thousand, 10]`.

### R2-m-4 — OWNER: a token that goes Ready during a short drop is never called
**Where:** §8 Call-out ("the **first** list after a load or a reconnect calls nothing"); tests 42, 43.
**Problem:** the called set (memory + `pos-board-called`) already stops repeats, yet every WS blip or hub restart (`1012`) during service silently skips the tokens that became Ready meanwhile — the board's main job.
**Fix (recommended default):** after a reconnect, diff against the last list shown when the board was offline < 5 min (else use the new list as the baseline); a page load keeps "calls nothing". Tests 42 / 43 change accordingly.

### R2-m-5 — §6.4 board session ends are written as post-commit; the code ends sessions in the commit
**Where:** §6.4 step 6 ("Post-commit, in order: … became the board → end every staff and admin session `'forced'` …; stopped being the board → end its `display` session `'forced'`"); Statements row ("≤ 1 staff + admin sessions"); code `commands/set-device-profile.ts:138–144` ("Ended in this commit as `'forced'`").
