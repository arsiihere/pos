## What holds (checked, not findings)

- **Blind count, server side:** the `shift` query, X and `CloseShift` return `expected_minor = null` before `ShiftCounted` (:843, #46). The H6-15 drop removes the last probe. Under H7-1 the count response is still the first reveal. A `HandoverCount` reveals only its own expected (:860), unchanged.
- **No money after close:** `AddPayment` (:792), `RecordPettyCash` (:864) and `OpenCashDrawer` (:870) need a shift in state `open`. `RemovePayment` refuses a non-open shift (:797–:798). `SettlePettyAdvance` lands on the caller's open shift. So after H7-1 a closed shift's expected cash can never move (the money model of Ran (2)).
- **Approvers:** `petty_cash` / `shift_variance` → holders of `close-shift-for-others`, never the requester (:366, D-1). B-1's `checkGrants` rule (holders must also hold `manage-own-shift`) fits `service.ts:759-768`.
- **Approval re-checks at apply time:** `discount`, `remove_service_charge`, `close_without_buyer_id`, `remove_comp`, `reopen_bill` each name the state they need (:358–:363), apart from H7-5's scope.
- **Credit series and outbox id:** gap-free per series (`invoices_series_number`), USIN unique across series (`invoices_ref`), outbox keyed by `invoice_id`; a crash resends the same USIN (:383).
- **Permission per command, `PrintReport`, Manager defaults:** see the H6-7 and H6-13 rows.
- **Privacy, events and hashes:** `CloseSplit` omits `buyer` from `payload_hash` and `processed_commands` (H-4 :482); `FiscalSubmitRejected` carries no body; worker logs are captured clean (#77); no 05 event or alert `values` carries text (:942); `ShiftVarianceAnswered` (H7-1) needs only ids, an amount and `has_note` / `note_id`; `invoice_buyers`, `fiscal_outbox`, `payment_references` and `fiscal_credentials` are never synced (:440, :541). The only new leak is H7-2's `print_jobs.payload`.
