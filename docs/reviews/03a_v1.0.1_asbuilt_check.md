### F3. WORDING, Minor. Dropped-line alert keys are wrong
**Location:** §4.2 marker (line 739) and §6.2a marker (line 1051).

**Evidence:** The spec says the key is `engine_line_dropped:<order_id>:<order_item_id>`, and that a refused batch gets "one key per listed id" / "the same per-line key". The code (`fires-alerts-tick.ts:92-101`, `:373`) does this instead:
- a single drop gets `engine_line_dropped:<order_item_id>`, with no order id;
- a refused batch raises **one** alert, keyed `<order_id>:<first offending id>`.

Tests pin both: `fires-alerts-tick.int.test.ts:255`, `:277-295`.

The key shape is AD-33 (22a)(2) (accepted), not the AD-8 condition. The §6.2a `due` list also leaves out "a queued drop makes `due` true" (`fires-alerts-tick.ts:248`).

**Fix:** Describe the keys as built, cite AD-33 (22a)(2), and add the queued-drop trigger to `due`.

### F6. WORDING, Minor. "Closes its key" misdescribes the answered-slip behaviour

### F7. WORDING, Major. The overload success test is described wrongly
**Location:** §3.5.6 marker (line 521), AD-15 reading (3).

**Evidence:** The spec says "Success at Λ = every line not at its cap fits". The code (`packages/engine/src/overload.ts:17-21`) uses "every line except the *hopeless* ones fits by `d_Λ`". A capped line that is not hopeless still has to fit. The code comment rejects the literal reading because it would let the search stop while a capped line is crowded out.

**Fix:** "every line except a hopeless one fits by its `d_Λ`; hopeless = a capped line that cannot fit by `d + max_late_ms` with every uncapped line removed".

### F8. WORDING, Minor. The `capped` recompute rule is simplified
**Location:** §3.5.6 marker (line 522), AD-16.

**Evidence:** The spec says "`capped` recomputed from the final placement (lateness > 0)". In the code (`overload.ts:24-25`, `:187-219`), a line is capped when either:
- it was placed after the others (hopeless lines, or lines left when the probe budget ran out); or
- its lateness is > 0 **and** ≥ `max_late_ms`.

Also, `capped` does not imply `max_late_ms ≠ null` (`state.ts:155-156`).

**Fix:** State the rule as built.

### F11. WORDING, Minor. The general writer-bug rule is not stated
**Location:** §3.4 AD-10 marker (line 442) and §3.3 "writer bugs" block.

**Evidence:**
- `ItemReturned` on a line that is not `served` is not a silent no-op. It raises `InvalidEvent` (`apply-event.ts:765`).
- More generally, every `InvalidEvent` throws in strict mode. In non-strict mode the event changes nothing except one diagnostic (`apply-event.ts:1248-1253`). Examples:
  - `FireDispatched` `station_mismatch` / `order_awaiting` (`:593-600`);
  - non-integer void or move shares;
  - `program_id_null`.
- Only the `ItemAdded` and `StockReserved` cases are written.

**Fix:** Name the `ItemReturned` exception in AD-10 and state the general rule.

### F12. WORDING, Minor. Routing fallback and `checkOrderable` detail
